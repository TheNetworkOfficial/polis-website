# Compact Text Banking status

Approved reference: `D:/CodexHome/visualizations/2026/11/02/polis-texting-status-approval/index.html`
and its `concept-overview.png` review board (November 2, 2026).

Campaign review and individual texting use the same compact header, one context
row, and a primary action within the viewport. Long messages scroll inside the
workspace. Informational updates have **Got it**; acknowledgement is scoped to
the actor, organization, campaign, revision and observed message. It changes no
campaign, recipient, financial or send state. A later update appears again.

Real holds remain visible after acknowledgement, dismissal or a failed status
read. Previous assignments open the verified existing campaign. Unconfirmed
requests keep their existing hold and offer the read-only saved-status action.
Closing details cannot request another allocation or enable sending.

Details open in a mobile bottom sheet or desktop side panel. More retains
campaign/team management, saved recipients, balance and the existing exit action.
Activity uses existing history and observed status messages; it invents no audit
events. Management confirmations, preparation consent and the exact per-message
Send proof remain in their original action handlers.

The normal recipient view shows one exact saved personalized preview. Its docked
Send targets that same item and uses the existing eligibility, funds, media,
receipt, expiry and uncertainty checks. Other saved recipients and full hold
explanations remain available under More. A held recipient offers review rather
than a second send route. Acceptance and delivery retain their distinct meanings.

The website uses canonical Civic Neon theme roles. Approved motion is a 200 ms
ease-out sheet entrance (20 px translation and 0.6 to 1 opacity) and a 1600 ms
linear status spinner. Reduced-motion mode disables both. Dialogs label their
headings, make the background inert, trap keyboard focus, close with Escape and
restore focus to a remaining toolbar control.

Workspace setup, renewal, funding and operation messages are consolidated only
when the rendered page contains the compact surface. They remain available in
its details; other website routes keep their existing presentation. Backend
contracts, provider integrations, customer data, geocoding, cost limits and
consent rules are unchanged.

Validation must cover the actual compiled workspace as well as source: light and
dark themes, mobile and desktop, acknowledgement, previous-assignment navigation,
unconfirmed reads, processing, normal sends, held recipients, management/details,
history, modal dismissal/focus, overflow and reduced-motion behavior. Local
fixtures use fictional data and must never contact a messaging provider.
